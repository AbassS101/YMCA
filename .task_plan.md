# Task Plan: Staff/Admin Editability of Member-Visible Content + Admin Feedback Visibility

## Architectural Overview

**Audit result: what members see vs. what staff can already change**

| Member-visible content | Source today | Staff-editable? |
|---|---|---|
| Membership plans, guest passes, donations, wellness packages, swim capacity, Child Watch rules, lesson pricing, campaigns, branding/hours, templates, feature toggles | `AppConfig` via Admin Center | ✅ yes |
| Class schedule / events | `scheduleRepo` (staff Schedules tab) | ✅ yes |
| Announcements / notices, surveys | `announcementRepo`, `surveyRepo` | ✅ yes |
| Forum topics/replies | `forumRepo` (staff delete/pin) | ✅ yes |
| Complaints & suggestions | `complaintSuggestionRepo` | ✅ for `manageComplaints` (only `member_services` dept shown) |
| **About page** (association, email, pillars, metrics, amenity list) | consts in `app/(member)/about.tsx` | ❌ |
| **Branch Amenities** | `AMENITIES` const in `app/(member)/branch-amenities.tsx` | ❌ |
| **Programs** | `PROGRAMS` const in `app/(member)/programs.tsx` | ❌ |
| **Busy Times** | arrays in `src/domain/busyness.ts` | ❌ |
| **Pool Schedule** (slot titles, closures, facility notice) | `src/domain/poolScheduleData.ts` | ❌ |
| **Aquatics session info** (session name, dates, registration dates) | `AQUATICS_SESSION_INFO` in `src/domain/aquaticsGuideData.ts` | ❌ |
| **Support tickets** (member "Report a problem / Request a feature") | `supportTicketRepo` | ❌ no staff inbox at all |

**Approach** — reuse the existing `AppConfig` section pipeline (defaults → `normalizeAppConfig` → `applyConfigPatch` → `assertConfigSectionAccess` → audit log → `useConfigEditor` screen → Admin Center tile). Add six new config sections, move the hard-coded constants into a new domain file as the defaults, switch member screens to read from `useAppConfig()`, and add one admin editor screen per section. Add a staff Support Tickets inbox and widen the complaints screen to show maintenance tickets for admins.

Permissions model (unchanged rules, extended):
- `staff_admin` (has `manageBusinessConfig`) and `it_admin` (has everything) can edit **every** new section.
- Directors edit the sections for their area via `CONFIG_SECTION_OWNERS`.
- New capability `manageSupportTickets` → admin + IT (included automatically via `ALL_CAPABILITIES`); excluded from Wellness Director.

Item lists that members see (amenities, programs, pillars) use `mergeById`, which re-adds missing default ids, so removal is done with a `hidden: boolean` flag per item (same idea as `AppConfigPlan.active`), never by deleting.

### 1. `src/domain/branchContent.ts` (NEW)
Holds types + default data moved verbatim out of the screens/domain files.

```ts
import type { Ionicons } from '@expo/vector-icons';
type IconName = keyof typeof Ionicons.glyphMap;

export type AboutPillar = { id: string; title: string; subtitle: string; description: string; icon: IconName; color: string; bg: string; hidden?: boolean };
export type AboutMetric = { id: string; label: string; value: string };
export type AboutAmenity = { id: string; name: string; icon: IconName };
export type AboutConfig = { association: string; email: string; pillars: AboutPillar[]; metrics: AboutMetric[]; amenities: AboutAmenity[] };

export type AmenityCategory = 'Aquatics' | 'Fitness' | 'Courts' | 'Family' | 'Wellness';
export type AmenityItem = { id: string; title: string; category: AmenityCategory; icon: IconName; badge?: string; description: string; details: string[]; scheduleAction?: { label: string; route: string }; hidden?: boolean };

export type ProgramSection = { id: string; title: string; category: string; badge?: string; icon: IconName; description: string; highlights: string[]; ctaText?: string; ctaRoute?: string; hidden?: boolean };

/** Occupancy 0-100 per open hour (OPEN_HOUR..CLOSE_HOUR-1); index 0 = Sunday. Always 7 rows × 17 values. */
export type BusyTimesConfig = { byDay: number[][]; note: string };

export type PoolSlotOverride = { title?: string; isClosed?: boolean; note?: string };
export type PoolScheduleConfig = {
  /** Banner shown at the top of the pool schedule, per pool. Blank = none. */
  facilityNotices: Record<string, string>;   // key = PoolId
  slotOverrides: Record<string, PoolSlotOverride>; // key = PoolTimeSlot.id
};

export type AquaticsSessionConfig = AquaticsSessionInfo; // re-export type from aquaticsGuideData

export const DEFAULT_ABOUT: AboutConfig;           // from about.tsx ASSOCIATION/EMAIL/PILLARS/METRICS/AMENITIES (add stable ids)
export const DEFAULT_AMENITIES: AmenityItem[];      // from branch-amenities.tsx AMENITIES
export const DEFAULT_PROGRAMS: ProgramSection[];    // from programs.tsx PROGRAMS
export const DEFAULT_BUSY_TIMES: BusyTimesConfig;   // byDay = [SUNDAY, WEEKDAY×4, FRIDAY, SATURDAY] from busyness.ts, note ''
export const DEFAULT_POOL_SCHEDULE: PoolScheduleConfig = { facilityNotices: {}, slotOverrides: {} };

export function visibleItems<T extends { hidden?: boolean }>(items: T[]): T[]; // filter !hidden
```

## Edge Cases & Failure Modes
- **Saved config from older app versions** lacks the new keys → `normalizeAppConfig` fills defaults (deepMerge/mergeById). Nothing in `demoStore.ts` needs migration.
- **Removing default list items**: `mergeById` re-adds deleted defaults, so editors must use `hidden` instead of delete; only custom (non-default id) items may be removed.
- **Busy times**: reject non-integers, <0, >100, wrong row counts; editor parses with `optionalWholeNumber` and blocks save on `NaN`.
- **Pool overrides referencing slot ids that no longer exist** (seed data changed): validator rejects on save; `applyPoolOverrides` simply ignores unknown keys at read time.
- **Closed slot** must not appear in `findOpenLapSwimSlots` / "Find a lap lane" results.
- **Feature toggles still apply**: amenities screen keeps the `child-watch` filter on `config.featureToggles.childWatch` after switching to config data.
- **Directors**: aquatics director must NOT be able to save `about`/`amenities` — enforced server-side by `assertConfigSectionAccess` (already generic), and tiles hidden by `adminCenterTiles`.
- **Support ticket member flow** (`listUserTickets` with `userId`) must keep working without a requester check.
- **Complaints**: Wellness Director remains excluded from complaints (existing deliberate rule in `staffCapabilities.ts`). If the user wants Wellness Director included, remove `c !== 'manageComplaints'` from its filter — flagged as an open decision, not done by default.
- **Audit log**: every new section automatically logs via `recordConfigAudit`; confirm `admin-audit.tsx` renders the new `CONFIG_SECTION_LABELS` (it reads labels by key — no change expected).
- **Icons** stored in config must be valid Ionicons names; editors pick from a fixed list rather than free text.
